## Send a message or file

Open a device or room. Type a message, choose **Send file**, or drop a file onto the conversation.

![An encrypted conversation between two paired browsers](/images/conversation.png)

Messages and files are **end-to-end encrypted**. They go directly between browsers when possible. If that connection fails, encrypted content goes **via server**. You can also enable **Via server** in the conversation toolbar.

The server cannot read the content. It can see delivery metadata, including recipients and sizes.

## Save files you need

A received file must pass its integrity check before you can save it. Verified files show **SHA-256 ✓**. A failed check offers a retry.

Choose **Save** before closing the browser or before a server copy expires. With streamed relay downloads, Save fetches the verified file again, so the server copy must still be available.

## Retry an interrupted transfer

| Transfer | What to choose |
| --- | --- |
| Direct transfer | **Resume** keeps received chunks and sends what is missing |
| Relay upload | **Restart upload** sends the file again from the beginning |
| Relay download | **Restart download** fetches the file again from the beginning |

**Gone** means the needed copy is no longer available. Ask the sender to send it again.

## How long server copies last

The relay is a temporary delivery buffer. By default, an item becomes unavailable when the first applicable condition is reached:

| Condition | Limit |
| --- | --- |
| All recipients have finished receiving or saving | Removed promptly |
| All participants are offline | 15 minutes |
| Only one participant remains in a direct chat | 3 hours; rooms are exempt |
| Item age | 3 days |
| Server restart or container replacement | Immediately |
| Relay capacity is needed | Older completed pending items may be removed |

The app shows an expiry countdown. Expired items cannot start another upload or download. An already-open download may finish. Disk cleanup runs every minute by default, but can be delayed.

## Capacity warnings

The app warns online participants when a file or text budget reaches **80%**. If space is needed, expired items are removed first, then the oldest completed pending items of the same kind. Affected online participants receive a notice.

Files and text have separate budgets, so a full file buffer still leaves room for chat. Active uploads and downloads are protected from capacity eviction. An item that cannot fit is rejected.

Operators can adjust the [capacity limits](/hosting/configuration). Copies already on your device are not removed by server cleanup.

## Message yourself

Open **This is you** in Devices to send encrypted notes or files to your browser identity.

- Use the same browser profile to recover them after a reload.
- Reconnect within **24 hours** of going offline.
- Each item has a **3-day maximum age** and can be removed by capacity cleanup.
- Clearing your browser identity prevents decryption. Server restarts erase these copies too.

For implementation details, see the [relay design and measurements](https://github.com/thesteau/evakage/blob/main/maintainer/relay-memory.md).
