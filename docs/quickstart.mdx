Evakage is in prerelease development. If you already have access to an instance,
open its URL in both browsers and skip to **Connect devices** below.

## Host your own instance

To use a published image:

```bash
git clone https://github.com/thesteau/evakage.git
cd evakage/deploy
cp .env.example .env
docker compose pull
docker compose up -d
```

See [deployment](/hosting/deployment) for updates, backups and image versions.

### Build from source

For a local source build, use the source Compose setup instead:

```bash
git clone https://github.com/thesteau/evakage.git
cd evakage
cp app/.env.example app/.env
docker compose -f app/compose.yaml up -d --build
```

Open `http://localhost:3712` on the host. For another device, expose the app through
an HTTPS reverse proxy with a certificate trusted by that device. Set `TRUST_PROXY=1`
only when clients reach the app through a proxy you control. WebCrypto, browser
identity and PWA features require HTTPS or localhost.

The source Compose setup reads `app/.env`. Copy the example as shown above,
then edit its values before starting Compose.

## Connect devices

1. Open the same server URL in both browsers.
2. On one device, show its private pairing code or **QR code**.
3. On the other device, choose **Connect**, then **Scan QR Code** or enter the
   private pairing code and choose **Join**.
4. Open the paired device and send text, a link or a file.

Advertising is off by default. Public advertised codes do not authorize pairing.
Creating rooms requires an optional account; joining by invitation, chatting and
sharing files work without one. Compare safety codes outside the app when verifying
a device's owner.

## Published images

The [deployment setup](/hosting/deployment) pulls `ghcr.io/thesteau/evakage:latest`
by default. `latest` tracks tested `main` commits.
For a stable release, edit the deployment Compose image tag to an actually published `vX.Y.Z` tag.
The prepared pipeline starts at `v1.0.0`; its configuration does not mean that
version is already available.

Learn about [privacy and storage](/hosting/privacy), [configuration](/hosting/configuration)
and [mobile limitations](/guides/mobile) before relying on a deployment.
